# Agent Development Notes

This is a Foldkit app. Read [`FOLDKIT.md`](./FOLDKIT.md) before writing any code in this project. It covers the architecture, the APIs, and the conventions the project is built on.

Root `application.ts` owns `Application`. When a root has a `composition/` directory, `composition/composition.ts` constructs and exports `ApplicationComposition`; `application.ts` retains root behavior such as Flags, init, and local EffectsLayer without constructing or forwarding the Composition or its builder. A compact root with no `composition/` directory keeps its Composition in `application.ts`. Import `defineApplication` from `foldkit`; author init through `Application.init(fn)`, and create every root Composition with `Application.toComposition(...)`, even when it has no children or Mounts. `Application.init` preserves the function's exact arguments, return type, Command requirements, and child evidence while checking its Model and Command result Messages. Give it one concrete function signature; optional, default, and rest parameters are supported. Wrap an overloaded helper or callable object in a concretely typed callback, and close over generic factory parameters outside the initializer. Composition has no `init` method: pass the Definition-owned init explicitly to `ApplicationComposition.toApplication(...)` or `ApplicationComposition.toElement(...)`, whose completion checks Flags, routing, container, the final child graph, and handler registration. For a compact root with no `composition/` directory, application.ts keeps straightforward Bindings beside the complete toComposition children/Mount lists. When composition/ exists, composition/composition.ts owns that graph and application.ts does not forward it. Extract substantial policies to composition/<child>.ts and expose them through its explicit composition/index.ts barrel; external consumers import from the composition barrel, never the policy or assembly implementation path. No separate root composition wrapper. A split feature uses composition.ts, including for Mount-only registrations. Shared Mount definitions live in mount.ts. Parent-owned Bindings from Application.bindChild(...) are passive relationship configuration; including them in the Composition children registers them. `entry.ts` imports each implementation piece from its real owner, lists those fields explicitly in completion, chooses browser inputs, calls `application.provide(ApplicationLayer)` when needed, and starts the Runtime. Keep root `ApplicationLayer` composition in `services.ts`; `entry.ts` imports it and starts the completed application. A small app can keep its logic in `application.ts`; split substantial Model, Message, init, update, and view logic into named files. Tests and server entries import the passive Composition and the pieces they need without starting the browser Runtime. Name the root Route union `ApplicationRoute` and the root provider `ApplicationLayer` (`ApplicationTestLayer` for its test alternative).
